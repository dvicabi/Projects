## User-facing changes

- Home controls, profile shortcut, settings, hidden accounts and the player use
  consistent typography, compact corners, neutral surfaces and blue primary
  actions, with light/dark colors and touch targets of at least 48dp.
- Home controls stack on a narrow screen or with enlarged text. The Activity
  context determines Hebrew RTL, including per-app language that differs from
  the process default. Usernames and the media timeline remain LTR.
- A selected shared Reel opens an opaque Activity immediately. The original
  screen must complete stopping before the selected native lookup or decoder
  preparation begins. Lookup and playback stay in that same Activity.
- Backgrounding releases the decoder. A resolved player restores position and
  waits for Play; an unfinished metadata lookup is canceled and must be reopened
  from the original attachment. Close/Back returns to the source screen.

## Defects found during critical review

| Finding | Correction |
| --- | --- |
| Fullscreen Dialog could leave the original Story running | Opaque Activity opens before lookup; stop completion is required |
| Stop callback can run before FragmentActivity finishes its own stop work | Handoff completion is posted to the next main-loop turn |
| Recreation could retain Window focus without delivering a new focus callback | Reconcile actual Window focus before preparation; restored playback still waits for Play |
| Framework insets could overwrite player side padding | Apply explicit insets plus content margins |
| Per-app Hebrew could inherit the process's English layout direction | Derive direction from the attached Context configuration |

Test setup issues found in earlier CI attempts were fixed without relaxing the
lifecycle, locale, touch-target or clipping assertions. The final run passed.

## Scope and remaining phone acceptance

The Android harness uses the production player, handoff, policy and UI with a
synthetic source Activity and local video. Its URL resolver and the two empty
patch-time native request bridge bodies are explicit test doubles. They are
never included in the signed APK. CI compiles the patch bundle; the full
proprietary-base APK is built and signed separately with the original private
release key. No private signing material or authenticated session was published.

**The signed APK has not been run against a logged-in Instagram account on the
user's phone.** Framework evidence does not prove the behavior of Instagram's
actual Story controller or live media lookup. The remaining acceptance check is
to open a shared Reel in a Story with audible video/music, verify that both
Story audio and progress stop during lookup and playback, press Back, and check
the Direct-message route. See [installation and phone checks](../docs/INSTALL_HE.md).
